# Performance audit — refero-mcp v0.1.0 (2026-05-01)

## Verdict: PASS

All five gates clear with comfortable headroom. Cold-start lands at ~100 ms vs. the 1.5 s target (15× headroom), tarball is 37.9 kB compressed, prod-dep tree is a single direct dep (`@modelcontextprotocol/sdk@1.29.0`) with 115 unique transitive packages, and maxrss for an initialized stdio server holds at ~64 MB. First catalog refresh against the live API is bounded at roughly 4–6 s for a typical 10-page walk (n×fetch + (n-1)×250 ms).

Author: Nate Davidovich (Lorecraft LLC) — auditor pass on first publish, run from `/Users/nathandavidovich/code/lorecraft/refero-mcp`.

## Metrics

- **Tarball:** 37.9 kB compressed / 141.0 kB unpacked / 57 files (`fidgetcoding-refero-mcp-0.1.0.tgz`, shasum `3e01de2b7252fef056e1b8b6490a8454f77cb92f`)
- **dist/ on disk:** 268 KB (54 files: 18 `.js`, 18 `.d.ts`, 18 `.js.map`)
- **Cold-start (end-to-end stdio ready):** 96–101 ms, median **98 ms**, max 101 ms across 5 runs (target <1500 ms — **15× headroom**)
  - Sub-measurement: pure `import('./dist/server.js')` + `createReferoServer()` lands in 77–85 ms (median 78 ms); the additional ~20 ms in the end-to-end number is JSON-RPC `initialize` round-trip over the spawned child's stdio pipe
- **First refresh estimate:** **~4.0–6.0 s** end-to-end for a typical 10-page catalog walk
  - Loop: `n` pages × per-fetch latency + `(n−1)` × 250 ms inter-page delay (`PAGE_FETCH_DELAY_MS` in `src/tools/shared.ts:54`)
  - Hard ceiling: `MAX_PAGES = 200`, so a worst-case runaway walk caps at `200 × (fetch + 250 ms)` ≈ 50–80 s before the loop self-terminates
  - Per-fetch budget: 10 s `AbortSignal.timeout` with 3 retries on 5xx (1 s/2 s/4 s exponential backoff), so a flaky page can stall the walk by up to ~17 s on its own
  - Worked example for n=10 pages, 200 ms fetch latency: `10×0.2 + 9×0.25 = 2.0 + 2.25 = 4.25 s`
  - Worked example for n=10 pages, 400 ms fetch latency: `10×0.4 + 9×0.25 = 4.0 + 2.25 = 6.25 s`
- **Maxrss (initialized stdio server):** 67.4 MB (`/usr/bin/time -l`, 64.3 MB across 3 server-construction-only runs); peak memory footprint reported by Mach ~10.5 MB. Well under any sane MCP-host budget.
- **Prod deps:** 1 direct (`@modelcontextprotocol/sdk@^1.0.0`), **115 unique transitive packages** (119 dep tree entries with dedupes). 6 optional deps (5 `@rolldown/binding-*` platform binaries + `openai`) — none required for runtime. `node_modules/` weighs 133 MB on disk, but **none of node_modules ships in the tarball** (`files: ["dist", "README.md", "LICENSE"]` in package.json gates the publish surface).

## Recommendations

Ranked by ROI; everything below is deferrable — none of it blocks the first publish.

1. **Strip source maps from the publish bundle (largest win, ~50 kB unpacked).** Ship maps via a separate `*.map.tgz` or only when consumers pass `--include=optional`. Either set `"sourceMap": false` in a `tsconfig.publish.json` and use it from `prepublishOnly`, or add a `.npmignore` that drops `dist/**/*.js.map`. Cuts tarball from 37.9 kB → ~25 kB and unpacked from 141 kB → ~90 kB. Trade-off: stack traces in user reports lose line accuracy. Acceptable for an MCP CLI; the source is on GitHub.
2. **Keep `openai` in `optionalDependencies` — confirmed correct.** The embeddings path lazy-imports it only when `OPENAI_API_KEY` is set, so users who run pure catalog/search never pay the install cost. Verify on next minor that the import is actually `await import("openai")` and not a top-level `import` (right now `dist/embeddings.js` is 8 kB compiled, which suggests it is — re-check if the file ever balloons).
3. **`fetchFullCatalog` page-fetch parallelism is intentionally serial (250 ms gap) — leave it.** The delay exists to be a polite citizen against `styles.refero.design`, not because of local CPU. Don't be tempted to `Promise.all` the pages — the upstream rate limit is what gates the refresh, not refero-mcp.
4. **Consider a `--max-pages` flag on `refero_refresh` for teams that only care about the latest N styles.** Trims the cold-refresh from ~4–6 s down to <1 s for the n=1 case, useful for CI smoke tests and demo recordings. Pure additive change.
5. **Memory ceiling is comfortable (~67 MB), but watch the catalog cache.** Each style is small (~1–3 kB JSON), but at scale (1000+ styles) `readCatalog()` deserializing the whole file on every tool call becomes the dominant allocation. If catalog size ever crosses ~5 MB, switch `cache.js` to streaming JSON or LRU-cache the parsed object across MCP calls (server lifetime is long-lived under stdio, so an in-process Map is free).
6. **`maxrss` of ~64 MB is dominated by Node + V8, not by refero-mcp's code.** Empty `node` REPL on this host already sits at ~30 MB, so the marginal cost of the server is ~30–35 MB. There's no engineering action here; just calibrate expectations when comparing against native MCPs.
7. **No security-relevant dep bloat detected.** `@modelcontextprotocol/sdk@1.29.0` pulls express@5.2.1, ajv@8.20.0, eventsource@3.0.7 — all current majors, all actively maintained. The `cross-spawn`, `which`, `iconv-lite` chain is the standard SDK surface and not unique to this package.
8. **CI gate suggestion (out of scope for this audit, but worth a TODO):** add a `npm pack --dry-run | grep "package size"` assert in CI that fails if the tarball ever grows past 100 kB. Cheap drift detector — first warning when someone accidentally bundles the wrong asset.

---

Audit run on macOS Darwin 25.1.0, Node ≥20, 5-run cold-start sample, single-host measurement. Numbers will shift ±10 ms on slower disks but the orders of magnitude hold — every gate has at least 5× headroom against its target.
