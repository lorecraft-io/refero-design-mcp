## Security audit

### Path traversal in `path-safety.ts` — PASS (with one caveat)

The `resolveProjectDir` whitelist (`src/path-safety.ts:27`) is `^[A-Za-z0-9](?:[A-Za-z0-9_.-]{0,98}[A-Za-z0-9])?$` plus explicit rejections for empty, NUL, `..`, leading dot, `/`, `\`, and length > 100. The implementation also enforces a "must be a direct child of `<vault>/05-Projects/` after resolve" defence-in-depth check (`src/path-safety.ts:73-82`). All known traversal vectors are blocked: `../`, absolute paths, NUL injection, mixed separators, encoded `..`, leading dot. **Caveat:** the test file expects 6 additional behaviors the current implementation doesn't cover (newline/tab rejection, lexical resolution preserving symlink path, `.git`-style names already covered but the test asserts a different message format). 6 path-safety tests fail — see Findings.

### Hardcoded developer path — RED finding (security/portability)

`src/path-safety.ts:24` hardcodes `DEFAULT_VAULT = "/Users/nathandavidovich/Desktop/BRAIN2"`. This default is reachable in the published package whenever `REFERO_MCP_VAULT_DIR` is unset. On every other user's machine that resolves to a non-existent path that the MCP will then try to `mkdir -p` inside. Two issues:
1. Leaks the developer's macOS username into the tarball (`/Users/nathandavidovich/...` is shipped in `dist/path-safety.js`).
2. Silently fails for every external user; the failure mode is "MCP appears to work but writes to a path no other process knows about".

**Fix:** require `REFERO_MCP_VAULT_DIR` to be set before any write tool runs; `null`-default and throw a friendly `PathSafetyError("save_to_project: REFERO_MCP_VAULT_DIR must be set")` in `vaultRoot()`. Same pattern as `config.ts`'s vaultDir handling, which already does this correctly.

### Fetch timeouts in `refero.ts` — PASS

`AbortSignal.timeout(10_000)` on every request (`src/refero.ts:60`). 4xx is terminal (no retry), 5xx and network `TypeError`s retry up to 3× with `[1s, 2s, 4s]` backoff. URL-encoded id parameter on `getById`, plus a uuid-shape pre-check (`src/refero.ts:154-158`). Body excerpts capped at 500 chars before being attached to thrown errors.

## Bullet-proof traits

### Cache works offline — PASS

`src/cache.ts` is filesystem-only — no network calls. `readCatalog()` returns `null` on missing/corrupt files (catch swallowed → caller refetches). `writeCatalog()` is atomic: writes to `<path>.tmp.<pid>.<ts>` then `rename()`. **One drift:** the brief and `config.ts` doc comment claim the default is `~/.refero-cache`. The actual default in `cache.ts:25` is `~/.cache/refero-mcp/`. They both work but disagree — pick one, fix the comment in `config.ts`. Low priority.

### Embedding fallback works without `OPENAI_API_KEY` — PASS

`getScorer()` (`src/embeddings.ts:222-251`) is structured to:
1. Check for `OPENAI_API_KEY` (via `loadConfig`).
2. Try to dynamically `import("openai")`.
3. On any failure (no key, no package, runtime throw), construct a `KeywordScorerImpl` and log the choice once via `console.error`.

The `KeywordScorerImpl` is a pure-JS BM25-lite over a 30-word stopword list with `\p{L}\p{N}` Unicode tokenization. Zero deps. Will always produce a score for any query.

### Schema warn-not-fail on missing fields — PASS

`src/types.ts:142-152` types `FullResultRaw.gradients/shapes/spacing/typography` and `meta.telemetry`/`screenshot` as `unknown` so consumers must narrow. `design-md.ts` uses optional chaining + `?? []` guards on every list read (`ds.colors ?? []`, `ds.fonts ?? full.fonts ?? []`, etc.). A style with no colors/fonts/dos/donts produces a valid (smaller) DESIGN.md.

### 1. RED — Cross-agent contract drift between Tester and Coder (test failures)

The Tester wrote tests against names/shapes the Coder didn't produce. Six test files break against the current source tree:

| File:line | Imports / asserts | Source export actually is | Impact |

| `tests/cache.test.ts:25-27` | `readCache`, `writeCache`, `isFresh` | `cache.ts` exports `readCatalog`/`writeCatalog`/`readStyle`/`writeStyle`/`readEmbeddings`/`writeEmbeddings`/`isFresh`. | 7 of 10 cache tests fail. |

**Recommendation:** the Coder runs a 30-min reconciliation pass that adds export aliases (or rename-to-spec) so the tests pass. No semantic changes needed, this is pure plumbing:
- `refero.ts`: `export { fetchRefero }` as an alias for whatever the underlying request fn is, or rename `requestJson` → `fetchRefero` and have `listPage`/`getById` call it. The internal helper is private.
- `cache.ts`: add `readCache`/`writeCache` thin wrappers that match the Tester's `(key, value)` signature, or expose a generic `readJsonOrNull<T>(relPath)`/`writeJsonAtomic(relPath, value)` pair.
- `tools/`: add `src/tools/index.ts` that re-exports `handleSearch`, `handleGet`, `handleList`, `handleSimilar`, `handleRefresh`, `handleDesignMd`.
- `design-md.ts`: rename frontmatter keys to match spec (`title`, `refero_id`, `captured_at`) — or accept the Tester's spec was wrong and update the test, but the Tester's keys are the more idiomatic Obsidian-vault shape.
- `embeddings.ts`: export `KeywordScorer` (alias) and accept an optional `{ env }` arg in `getScorer()` to make it injectable for tests.
- `path-safety.ts`: lift the explicit newline/tab rejection out of the regex into a named check so error messages match the Tester's expected strings; preserve symlink-lexical-resolution semantics (use `path.resolve` only, never `realpath`).

This is the **only RED finding** — once it's done, the rest of the scaffold is clean.

### 2. RED — Hardcoded developer-machine default vault path

`src/path-safety.ts:24` `DEFAULT_VAULT = "/Users/nathandavidovich/Desktop/BRAIN2"`.

This default ships in `dist/path-safety.js` to every consumer. Two costs: (a) leaks the dev's macOS path into the tarball; (b) silently fails on every other user (creates phantom directories, then writes to nowhere useful). `config.ts` already handles this correctly — `vaultDir` is `string | null` and writes that need it must throw if it's null. `path-safety.ts` should mirror that: no default, raise `PathSafetyError("save_to_project: REFERO_MCP_VAULT_DIR is required for project-relative writes")` when the env is unset.

### 3. YELLOW — vitest config uses deprecated `poolOptions.forks`

`vitest.config.ts:32-37` uses the vitest 3.x shape:
```ts
pool: "forks",
poolOptions: {
  forks: { singleFork: false, isolate: true },
},
```
vitest 4 (which the package pins via `"vitest": "^4.0.0"`) has removed `poolOptions` — they're now top-level. CI emits `DEPRECATED test.poolOptions was removed in Vitest 4.` The tests still run, but the config will break in the next vitest minor. Migrate to:
```ts
pool: "forks",
isolate: true,
poolOptions: { forks: { singleFork: false } },
```
(or whatever the migration guide spells out — it's a 5-min change).

### 4. YELLOW — `cache.ts` and `config.ts` disagree on default cache directory

- `config.ts:41`: `DEFAULT_REFERO_CACHE_DIR = join(homedir(), ".refero-cache")`
- `cache.ts:25`: default is `join(homedir(), ".cache", "refero-mcp")`

The README and `.gitignore` mention `.refero-cache/`. Both work — they're never used together in practice — but new contributors will trip on the mismatch. Pick one (recommend `~/.cache/refero-mcp/` for XDG-friendliness), update the other.

### 5. YELLOW — `any` casts in embeddings.ts have no justification comment

`src/embeddings.ts:121` and `src/embeddings.ts:130` use `: any` for the `openai` dynamic-import shape. The user's CLAUDE.md says "No `any` without justification comment". Add a single-line eslint-disable + reason next to each.

### 6. INFO — `pre-commit` hook gracefully no-ops if `gitleaks` is not installed

This is the right call for a multi-machine scaffold (the husky hook runs on every contributor's box; failing-closed on missing gitleaks would block clean commits on a fresh checkout). The ci.yml does NOT yet wire `scripts/security-scan.sh` — that's an enhancement to consider when adding `secrets.NPM_TOKEN` for the publish flow.
